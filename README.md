# nice-numbers-certified

Machine-checked statements that a particular base has **no** nice number.

A number `n` is **nice in base `b`** when the base-`b` digits of `n^2` and `n^3` together use
every digit `0 … b-1` exactly once. The only one known is 69 in base 10 (`69^2 = 4761`,
`69^3 = 328509`). More generally `n` is **`(e1,e2)`-nice** when `n^e1` and `n^e2` share the
digits out that way.

The theorems for all bases are in
[nice-numbers-lean](https://github.com/Janzert/nice-numbers-lean), and this project depends
on it. Each result here is stated with that project's `Pandigital`, so "no nice number in
base 17" means exactly what it means there. Proofs are in Lean 4 core, with no Mathlib, no
`sorry` and no `native_decide`.

## What is proved

| base | pair | statement | intervals | candidates checked one by one |
|---|---|---|---|---|
| 17 | `(2,3)` | `Nice.Cert.base_seventeen_empty_2_3` | 392 | 5 831 |

## How it works

[`NiceCertified/Checker.lean`](NiceCertified/Checker.lean) defines a certificate and proves
one theorem about it, `no_nice_of_cert`. A certificate is a chain of consecutive intervals
covering every `n` whose powers could have `b` digits between them. Each interval carries a
reason that nothing in it is nice:

- **wrong lengths:** across the interval, the digit counts of `n^e1` and `n^e2` are
  constant and do not add up to `b`;
- **top-digit clash:** the leading digits of both powers are the same for every `n` in the
  interval, and they already repeat a digit. That rules out the whole interval from its two
  endpoints;
- **scanned:** every `n` in the interval is checked in full.

The checker is a `Bool` function, and the kernel evaluates it on a base's certificate with
`decide +kernel`. That is all a base costs: the soundness proof is done once, for every
base.

The certificates are generated by [`gen/gen.py`](gen/gen.py), which uses only the Python
standard library. Nothing about the generator needs to be trusted. If it emits a wrong
certificate, the kernel rejects it. For example, the certificate it emits for base 10 fails,
because 69 is in the band.

## Checking it

```bash
lake build
```

This fetches nice-numbers-lean at the revision pinned in
[`lakefile.toml`](lakefile.toml) and builds both projects. At the end it prints
`#print axioms` for each theorem, which should list only `propext`, `Classical.choice` and
`Quot.sound`. The `lean-toolchain` file selects Lean v4.33.0.

To regenerate a base's module:

```bash
python3 gen/gen.py 17 2 3 17 > NiceCertified/Base17.lean
```

The arguments are the base, the exponent pair, and the widest interval the generator scans
instead of splitting further.

## Limits

A certificate is one list literal, and Lean's elaborator hits its recursion limit on a
list of about 6 000 entries. Scanning costs about 2.3 ms of kernel time per candidate.
Bases much past 20 will need the kernel to rebuild the interval tree itself, from a proof
that the construction is sound, rather than read it as a list.
